koh — peer-to-peer remote shell, headless jobs, delta sync, and fux sessions over iroh QUIC.

SERVER is a saved name (`koh servers add NAME ID [--direct IP:PORT | --relay-url URL]`) or an
endpoint id. Only `connect` needs a terminal. `koh help-agents` is this and recipes for scripts.

Keys & peers:
  koh id [client|server]                         print the client id the server should allow (or server)
  koh key reset [client|server] --yes            delete key; next use generates a new id
  koh servers [add NAME ID [--direct IP:PORT | --relay-url URL] | rm NAME | rename OLD NEW]
  koh clients [add NAME ID [--cp DIR | --exec DIR] | rm NAME | rename OLD NEW]
  koh serve [--direct BIND] [--allow ID]... [--shell PROG] [--no-relay]
            [--max-connections N] [--max-sessions N]   (1 to 65535, 64 each; past them a client exits 75)
            (needs kill(1) on its PATH: jobs are ended and commands hung up with it;
             and id(1) where XDG_RUNTIME_DIR is not set: its state is kept under `id -u`)

Raw commands (no PTY; separate stdout/stderr; stdin EOF; hangup on drop):
  koh exec SERVER [--sync DIR] [-C DIR] [--json] -- PROG ARG...
  koh exec SERVER [--sync DIR] [-C DIR] [--json] --sh 'SHELL LINE'
  koh rsh HOST WORD...                           ssh-shaped exec (words joined with spaces for sh -c)
            rsync -a --delete --exclude target -e 'koh rsh' src/ box:dst/
            GIT_SSH_COMMAND='koh rsh' git clone box:repo.git
            tar -C src -cf - . | koh rsh box 'mkdir -p dst && tar -C dst -xf -'
            (only --key-file, --direct, --relay-url, -- before HOST; ssh flags like -l/-p/-o exit 2)

Headless persistent jobs (raw append-only logs; outlive koh and network drops):
  koh run SERVER [--name NAME] [--sync DIR] [-C DIR] [--json] -- PROG ARG...
  koh jobs SERVER [NAME] [--json]
  koh logs SERVER NAME [--tail N | --all] [-f|--follow]
  koh wait SERVER NAME [--text SUBSTR] [--tail N] [--timeout SECS] [--json]   (a job; a session: below)
  koh kill SERVER NAME [--signal TERM|KILL|INT|HUP] [--json]

Delta file sync (blake3 hashes, atomic replace):
  koh cp [-r] [--delete] [--exclude PAT]... [-p] [--dry-run] [--json] SRC... SERVER:DST
  koh cp [-r] [--delete] [--exclude PAT]... [-p] [--dry-run] [--json] SERVER:SRC... DST
            (--delete is for one directory: with a file it is refused)

Sessions (each a fux pane on the server, in koh's own fux session, kept by `koh hold`;
`koh serve` prints the folder, and `koh fux view FOLDER` there shows them all as tabs):
  koh connect SERVER [--session NAME | --new] [-C DIR] [-- PROG ARG...]
            the session NAME, started if there is none; with no name the newest that lives,
            or a new one (always with --new or a program). Leave with Ctrl-] . (Ctrl-] twice
            types one): koh's one key. Every other key is the session's.
            Ends with the session's program: its status, 128+N if signal N ended it, 1 if
            nothing says how it ended. The session's viewer runs on the server, and this
            terminal shows what it draws. While there is no link koh says so and dials again:
            what is typed then is held (64 KiB), and Ctrl-] . leaves then too.
  koh fux ...                                    fux itself, the one that reads koh's panes
            (it and `koh hold` run on this machine, and ask no server)
  koh sessions SERVER [--json]
            each session as its folder on the server says it is, the oldest first: name, attached
            or detached, what became of its program (running, exited N, killed N, hungup, or
            ended where nothing says how), busy while a command runs, the last command's exit
            code, size, title
  koh output SERVER --session NAME [--last] [--json]
            the screen it shows; with --last what its last command printed, from where its
            output began to where it ended (a line break is added to a last line without one)
  koh wait SERVER --session NAME [--timeout SECS] [--json]
            for the first command that ends there after it was asked (so ask before you type
            the command): prints what that one printed and exits with its code. Or until the
            session ends: its screen, and its program's status as `koh connect` gives it.
            After SECS: the screen, and 124. Not with JOB, --text or --tail, which are a job's.
            (--last and wait go by a shell's marks of its prompts, OSC 133: `koh help-agents`
            has the lines for bash, and nearly the same three as a script over the files.)

Global options: --key-file PATH, --direct IP:PORT, --relay-url URL, --json
Exit codes: 0 ok, 1 failed, 2 usage, 3 unreachable, 4 refused/out-of-scope, 75 busy,
            124 timeout, 126 cannot start, 127 not found, 255 koh internal error.
            (`exec`, `rsh`, `wait`, `logs -f` and `connect` exit with the remote
            command's exit status.)
            `koh serve` exits 75 when another `koh serve` already holds its key.
